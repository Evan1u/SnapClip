# SnapClip 产品需求文档（PRD）

> 文档状态：v1.0 / 可开发
> 更新日期：2026-08-23
> 目标平台：Apple Silicon，macOS 14 及以上
> 主要读者：产品所有者、协作开发者、AI 编码代理

## 1. 产品摘要

SnapClip 是一款只驻留在 macOS 菜单栏的轻量截图工具。用户通过全局快捷键完成选区、窗口或主显示器截图；截图会先进入编辑器，确认后写入系统剪贴板，并在菜单栏中保留最近三张会话内历史。用户可在编辑器中二次裁剪、标注、打马赛克、旋转文字，或使用 Apple Vision 在本地识别并复制图片文字。

首版坚持原生、离线和零第三方运行时依赖：不上传截图、不创建账号、不做持久历史、不接入 ChatGPT、不进行分析统计。

## 2. 背景与问题

macOS 自带截图功能可以把图片保存到桌面或剪贴板，但当用户需要连续处理几张截图时，系统剪贴板只保留最后一次结果，旧截图需要重新截取或从文件中寻找。重量级截图工具通常附带标注、云同步、团队协作等功能，增加了包体、资源占用和隐私面。

SnapClip 解决的是一个更窄的问题：让用户用接近系统截图的交互获得“当前截图 + 最近三张历史 + 本地 OCR”，且工具在空闲时几乎不消耗 CPU。

## 3. 产品目标

### 3.1 目标

1. 用户可以在任何应用中用全局快捷键启动截图。
2. 截图完成后无需额外操作即可粘贴到当前工作流。
3. 用户可以从菜单栏重新选择最近三张截图。
4. 用户可以在不上传图片的情况下复制截图中的中英文文字。
5. 应用保持低资源占用、无后台轮询和清晰的隐私边界。

### 3.2 非目标

首版不包含：

- 滚动截图、录屏。
- 截图文件库、跨设备同步或云端存储。
- ChatGPT、图片搜索或任何网络请求。
- 多用户、账号、订阅、分析统计或崩溃上传。
- 自动更新、Developer ID 公证或 Mac App Store 分发。
- Intel Mac 和 macOS 13 及以下版本。
- 一次快捷键生成多个显示器截图。

## 4. 用户与核心场景

### 4.1 目标用户

- 高频使用复制粘贴、文档、聊天和研发工具的个人 Mac 用户。
- 希望截图工具足够快、足够私密，不需要复杂编辑功能的用户。

### 4.2 核心任务

1. **快速截取并粘贴**：用户按快捷键、框选区域，然后直接在目标应用中按 `⌘V`。
2. **找回上一张截图**：用户截了新图后发现还需要上一张，从菜单栏单击旧图即可重新复制。
3. **截取一个窗口**：用户启动交互截图、按空格切换为窗口模式，再点击窗口。
4. **复制图片文字**：用户在某张历史截图上点击“复制文字”，随后把识别结果粘贴到文档。
5. **查看并摘取局部文字**：用户点击“编辑”，在编辑器 OCR 模式中直接拖选图片中的文字，通过右键或 `⌘C` 复制所选片段，不生成长期文件。

## 6. 信息架构与界面

SnapClip 不显示 Dock 图标。菜单栏图标使用 SF Symbol，并有可访问性名称“SnapClip”。点击图标打开 `.window` 风格弹窗。

界面采用“暖色暗房工作台”方向：以暖象牙/暖石墨为自适应背景、暖白/暖灰为内容表面、暖珊瑚为唯一品牌强调色。结构保持紧凑并优先展示截图；系统 Serif 只用于品牌标题，系统 Sans-serif 用于正文，系统 Monospaced 用于快捷键、历史编号和容量。所有功能图标使用 SF Symbols，不使用渐变、emoji、固定纯黑主题或第三方图标。完整 token 和使用边界见 `docs/brand-spec.md`。

### 6.1 菜单栏弹窗

从上到下排列：

1. 标题与短状态：就绪、正在截图、正在识别、已复制或错误。
2. “截取选区或窗口”按钮，显示当前快捷键。
3. “截取主显示器”按钮，显示当前快捷键。
4. 最近截图列表，最新在最上方，最多三项。
5. 有历史时显示“清空历史”。
6. “设置”和“退出 SnapClip”。

历史标题同时显示 `当前数量 / 03`，每项以 `截图 01` 等会话内位置编号强化工作台层级；编号只代表当前倒序位置，不是持久 ID。两个截图入口默认都使用中性暖白/暖灰表面，鼠标悬停的入口切换为珊瑚色、按下时进一步加深；禁用项不响应悬停视觉。历史卡片悬停时加深同色系边框、轻微抬升表面但不整块填充强调色，上下两区统一使用 120 ms ease-out 过渡。空历史使用取景框空状态，不显示无效入口。

每条历史卡片包含：

- 保持比例的缩略图和截图时间。
- 单击缩略图：将图片复制回剪贴板，不改变历史顺序。
- “打开”按钮：在应用内预览。
- “复制文字”按钮：按需 OCR；识别期间显示进度并禁用重复请求。
- “保存”按钮：把该项原始 PNG 直接保存到当前用户桌面，不改变历史和剪贴板。
- 全应用同一时间最多执行一个 OCR；识别期间其他截图仍可复制或预览，但其他未缓存项目的“复制文字”暂不可用。

“打开”后的图片内文字选择与卡片“复制文字”用途不同：前者复制用户在图片原位置选中的局部文字，后者一键复制整张图的 OCR 全文。

### 6.2 预览窗口

- 全应用只复用一个预览窗口。
- 窗口初始大小不超过可见屏幕的 80%，图片按比例适配。
- 切换历史图片时更新现有窗口，不创建多个窗口。
- 图片立即显示，VisionKit 实况文本在后台异步分析；分析期间不阻塞查看、缩放或关闭窗口。
- 分析成功后可在图片原位置拖选文字，支持系统右键“复制”和 `⌘C`，只复制当前选中片段。
- 分析中、未发现文字、不支持或失败时显示轻量状态；任何失败都不影响图片预览，也不改剪贴板。
- 关闭预览不会删除历史。
- 预览只解码并分析当前图片；关闭或切换时取消旧分析、清除旧选区并释放不再使用的位图与分析对象。
- 每次分析使用请求代次校验，上一张图片晚到的结果不得覆盖当前图片。

### 6.3 设置窗口

- 选区/窗口快捷键录制器。
- 主显示器全屏快捷键录制器。
- “播放截图音效”开关，默认开启。
- “登录时启动”开关，默认关闭。
- “恢复默认设置”。
- 快捷键冲突或登录项需要系统批准时显示内联说明。
- 顶部显示品牌标记与运行状态；底部显示“仅在本机、仅限当前会话”的隐私说明。
- 窗口为 600×680 pt，内容在较小可见区域仍可滚动；浅色和深色模式保持相同信息层级。

“恢复默认设置”只恢复两组快捷键和截图音效；不修改登录启动状态，也不影响当前历史。

## 7. 功能需求

### 7.1 截图

| ID | 需求 | 验收条件 |
|---|---|---|
| CAP-01 | `⇧⌘4` 启动交互式截图 | SnapClip 运行时不触发系统截图；默认进入选区；空格切换窗口；Esc 取消 |
| CAP-02 | `⇧⌘3` 截取主显示器全屏 | SnapClip 运行时不触发系统截图；一次只产生一张图片 |
| CAP-03 | 菜单按钮提供相同两种截图入口 | 行为与快捷键一致 |
| CAP-04 | 截图期间拒绝重复触发 | 同一时间最多一个截图进程 |
| CAP-05 | 成功后播放系统截图音效 | 设置关闭时保持静音 |
| CAP-06 | 成功后菜单栏图标短暂闪动 | 不使用持续动画或轮询 |
| CAP-07 | 取消截图不算错误 | 不修改剪贴板、历史和预览 |

截图实现使用 `/usr/sbin/screencapture`：

- 交互截图参数：`-i -t png <临时路径>`。
- 主显示器截图参数：`-m -t png <临时路径>`。
- 静音时追加 `-x`。
- 声音由 `screencapture` 的系统行为产生；应用不额外播放音频。音效开关保存在 `UserDefaults`。
- 临时文件名使用 UUID，位于系统临时目录。
- 进程结束后读取 PNG；无论成功、取消或失败，都尝试删除临时文件。
- 退出进程状态为 0 或 1 且没有输出文件时按取消处理；状态 1 即使生成了文件也按执行失败处理；只有状态 0 且存在可解码 PNG 才算成功；其他非零状态按执行失败处理。
- 应用启动时以尽力而为方式删除系统临时目录中超过一小时的 `SnapClip-*.png`，用于回收崩溃遗留文件；不会扫描或删除其他文件。

### 7.2 剪贴板

| ID | 需求 | 验收条件 |
|---|---|---|
| CLIP-01 | 成功截图立即写入通用剪贴板 | 常见聊天、文档和图片应用可直接粘贴 |
| CLIP-02 | 写图同时提供 PNG 与 TIFF 表示 | 兼顾保真度和 AppKit 兼容性 |
| CLIP-03 | 单击任意历史缩略图重新复制 | 不新增、不移动历史项 |
| CLIP-04 | OCR 成功后写入纯文本 | 图片剪贴板内容被识别文字替换 |

截图事务顺序固定为“校验 PNG → 写剪贴板 → 加入历史”。PNG 是必须表示，TIFF 是可生成时附加的兼容表示；单次 `NSPasteboardItem` 写入成功才算剪贴板成功。写入失败时不加入历史，但由于 NSPasteboard 的写入流程会先清空旧内容，不能承诺恢复此前剪贴板内容。

重新复制历史图片失败时保留历史和顺序，显示错误，用户可再次点击重试。OCR 识别成功后先缓存文字再写入剪贴板；若文字写入失败，项目仍保持 `completed`，再次点击会直接用缓存文字重试而不重复运行 Vision。

### 7.3 三项历史

| ID | 需求 | 验收条件 |
|---|---|---|
| HIST-01 | 历史按截图时间倒序 | 最新截图始终位于第一项 |
| HIST-02 | 最多保留三张 | 第四张成功截图自动淘汰最旧一张 |
| HIST-03 | 图片载荷只保存压缩 PNG 数据 | 截图时间、OCR 状态和缓存文字作为轻量元数据保存；不长期缓存三张完整解码位图 |
| HIST-04 | 退出即清空 | 重启应用后历史为空 |
| HIST-05 | 支持手动清空 | 清空后菜单显示空状态 |
| HIST-06 | 将任意历史项保存到桌面 | 使用 `SnapClip yyyy-MM-dd HH.mm.ss.png`；重名时追加空格序号且不覆盖已有文件 |

桌面保存使用截图自身的捕获时间命名，例如 `SnapClip 2026-08-23 16.05.30.png`。只有同名文件已经存在时才生成 `SnapClip 2026-08-23 16.05.30 2.png`、` 3.png`；成功后显示最终文件名，失败时保留剪贴板、历史顺序和 OCR 状态并允许重试。

### 7.4 OCR

| ID | 需求 | 验收条件 |
|---|---|---|
| OCR-01 | 用户点击时才识别 | 截图完成后不自动消耗 OCR 资源 |
| OCR-02 | 使用 Apple Vision 本地识别 | 不发生网络请求 |
| OCR-03 | 支持简中、繁中和英文 | 配置 `zh-Hans`、`zh-Hant`、`en-US` |
| OCR-04 | 结果按自然阅读顺序组合 | 从上到下；同一行从左到右；保留换行 |
| OCR-05 | 会话内缓存识别结果 | 同一截图再次复制文字无需重复识别 |
| OCR-06 | 无文字或失败有明确反馈 | 不覆盖现有剪贴板内容 |
| OCR-07 | 全局同一时间最多一个识别任务 | 重复点击或另一项目的新请求不会启动第二个 Vision 任务 |

识别失败会把该项目标记为失败，但允许用户再次点击重试；“未识别到文字”同样属于可重试的 `failed`，不缓存空结果。识别成功的文本在当前会话内缓存。文字排序先按纵向中点从上到下建立稳定候选序列；以每行第一框的纵向中点和高度为锚点，将纵向差不超过较大框高 55% 的后续框归入该行，再把行内框按横坐标从左到右排序。这样不使用可能不满足传递性的逐对比较器。首版不承诺复杂分栏、竖排或任意旋转内容的版面还原，只要求不崩溃并返回可用的最佳结果。

#### 7.4.1 图片内实况文本

| ID | 需求 | 验收条件 |
|---|---|---|
| LIVE-01 | 打开预览后异步分析可选择文字 | 图片先显示，分析不阻塞窗口交互 |
| LIVE-02 | 在图片原位置选择文字 | 可拖选中文、英文或混合文字，并看见系统选区反馈 |
| LIVE-03 | 复制局部文字 | 右键“复制”和 `⌘C` 都只写入当前选中片段 |
| LIVE-04 | 切图与关窗清理 | 取消旧任务、清除选区与分析对象，晚到结果不得串图 |
| LIVE-05 | 无结果时可降级 | 不支持、无文字或失败时仍可查看图片，且不改剪贴板与历史 |

实况文本使用 VisionKit 的空间分析结果，只服务当前预览图片，不写入 `ScreenshotItem` 或长期缓存。历史卡片的 Vision OCR 全文缓存保持独立，两者互不覆盖。

### 7.5 全局快捷键

- 默认系统截图键使用 session 级活动 `CGEventTap` 在事件队列头部匹配并吞掉按键，不使用轮询；SnapClip 退出后事件拦截自动消失，macOS 原行为立即恢复。
- 用户自定义的非系统截图组合使用 Carbon `RegisterEventHotKey`。
- 默认值：
  - 交互截图：Shift + Command + 4。
  - 主显示器：Shift + Command + 3。
- 不修改 `com.apple.symbolichotkeys` 或其他系统快捷键偏好，避免应用崩溃后留下全局副作用。
- 旧版本仍使用两组出厂值 `⌃⌥4`/`⌃⌥3` 时自动迁移到新默认；只要用户明确改过其中任意一组，就保留两组现有配置。
- 快捷键配置保存到 `UserDefaults`。
- 注册新快捷键前先尝试注册；失败时恢复旧快捷键和旧配置。
- 两个 SnapClip 快捷键不得相同。
- 录制器接受“至少一个 Control、Option、Shift 或 Command 修饰键 + 一个非修饰键”；Esc 取消本次录制。显示名称遵循当前键盘布局，底层保存物理 key code 与修饰键。
- 使用 `⇧⌘3/4` 需要辅助功能权限；未授权时不启用这两组快捷键，菜单截图按钮仍可使用，并展示授权、打开系统设置和重新检测入口。
- 若应用启动时自定义快捷键发生系统冲突，两组 SnapClip 快捷键均不启用，菜单截图按钮仍可使用；用户可在设置中换成可注册的组合。
- 用户修改任意一组快捷键时，服务以“新组合 + 另一组当前组合”原子地重新注册两组；任一注册失败则两组都回滚到修改前的注册状态和设置值。
- “恢复默认设置”也以两组快捷键为一个原子事务；成功后恢复 `⇧⌘4`、`⇧⌘3` 和截图音效，登录启动与历史不变。失败时快捷键和音效都保持恢复操作前的值；若值已默认但权限未就绪，仍必须重新尝试接管并展示结果。
- 应用退出时注销所有已注册快捷键和事件处理器。

### 7.6 登录启动

- 使用 `SMAppService.mainApp`。
- 默认关闭，以系统实际状态为真值。
- 注册、取消注册和“需要用户批准”都应反馈到设置界面。
- 由于 `SMAppService` 和屏幕录制 TCC 授权都依赖稳定的代码签名身份，开发构建使用 Xcode Personal Team 的 Apple Development 签名；裸命令行或 ad-hoc 产物不保证登录启动与既有屏幕录制授权可用。

## 8. 状态与异常处理

### 8.1 应用状态

运行状态不是互斥枚举，而是三个正交部分：

- `isCapturing: Bool`：截图进程运行中时，新的截图按钮与快捷键请求被忽略。
- `recognizingItemID: UUID?`：全局最多一个 OCR；截图流程可与 OCR 并行，其他历史复制和预览仍可用。
- `statusMessage + statusIsError`：显示最近一次反馈或错误，不作为任务是否运行的唯一真值。

因此同一时间最多存在一个截图任务和一个 OCR 任务，二者可以同时运行，且都不得阻塞主线程。

### 8.2 错误场景

| 场景 | 行为 |
|---|---|
| 用户按 Esc 取消 | 静默回到就绪状态 |
| 屏幕录制权限不足 | 首次请求若立即返回允许，则继续原截图；若返回拒绝，则解释权限用途并提供“打开系统设置”，授权后由用户再次触发截图 |
| `screencapture` 启动失败 | 保留剪贴板和历史，显示可诊断错误 |
| 进程状态 0 或 1 且无文件 | 视为取消或无输出，不加入历史 |
| PNG 无法解码 | 删除临时文件，显示图片无效 |
| OCR 未发现文字 | 显示“未识别到文字”，不改剪贴板 |
| VisionKit 不支持、未发现可选择文字或分析失败 | 图片继续可查看，显示对应轻量状态，不改剪贴板与历史 |
| 预览切图后收到上一张图片的分析结果 | 请求代次校验拒绝晚到结果，不把旧文字覆盖到当前图片 |
| 历史图片写入剪贴板失败 | 保持历史不变，显示错误并允许再次点击 |
| OCR 文字写入剪贴板失败 | 保留已缓存文字，显示错误；再次点击只重试写入 |
| 快捷键冲突 | 保留原快捷键并显示冲突提示 |
| 登录项需要批准 | 引导用户打开“系统设置 > 通用 > 登录项” |

### 8.3 历史、预览与异步任务边界

- 清空或淘汰历史不会关闭当前预览；预览窗口保留已经解码的当前图片，直到用户关闭窗口或打开另一张图片。
- 某项 OCR 期间若该项被清空或淘汰，任务不强制取消；任务结束后丢弃结果且不改剪贴板。任务结束前仍占用全局唯一 OCR 槽位。
- 预览切换图片或关闭窗口时取消 VisionKit 分析并使当前请求代次失效；即使底层任务稍后返回，也丢弃其结果。
- 菜单缩略图只在对应卡片出现时通过 ImageIO 按 236 像素最大边降采样，视图销毁时释放；不把三张 4K 原图解码为全尺寸缩略位图，也不建立跨会话或无上限缓存。

## 9. 数据模型

### 9.1 CaptureMode

- `interactive`：选区或窗口。
- `mainDisplay`：主显示器全屏。

### 9.2 ScreenshotItem

- `id: UUID`
- `capturedAt: Date`
- `pngData: Data`
- `recognizedText: String?`
- `ocrState: idle | recognizing | completed | failed`

不存储来源应用、窗口标题、鼠标位置或屏幕内容之外的元数据。

## 10. 技术架构

### 10.1 技术栈

- Xcode 工程作为正式构建入口。
- Swift 6，SwiftUI 应用生命周期。
- SwiftUI：菜单栏、设置和历史列表。
- AppKit：剪贴板、应用激活和独立预览窗口。
- VisionKit：预览图片内的实况文本定位、选择与系统复制交互。
- Vision：本地 OCR。
- Carbon/HIToolbox：用户自定义全局快捷键。
- CoreGraphics/ApplicationServices：接管系统截图键、辅助功能权限，以及屏幕录制权限预检和请求。
- ServiceManagement：登录启动。

### 10.2 内部边界

- `CaptureService`：异步截图，区分成功、取消、权限不足和执行失败。
- `HistoryStore`：三项环形历史及 OCR 缓存更新。
- `ClipboardService`：复制 PNG/TIFF 图片和纯文本。
- `DesktopExportService`：异步把用户选择的原始 PNG 保存到实际桌面目录，负责可读命名、同名序号和无覆盖提交。
- `OCRService`：图片解码、Vision 请求和文本排序。
- `HotKeyService`：用事件拦截接管系统截图键、用 Carbon 注册自定义键，并负责更新、注销、录制模式和冲突回滚。
- `LoginItemService`：读取与更新系统登录项状态。
- `ScreenCapturePermissionService`：权限预检、请求与系统设置跳转。
- `PreviewWindowController`：复用单一图片窗口，协调 VisionKit 分析、选区、请求代次校验与关闭释放。
- `AppModel`：`@MainActor` 状态协调器，负责将服务结果映射到 UI。

### 10.3 并发规则

- 所有 UI 状态在主 Actor 更新。
- 截图进程等待和 OCR 在异步任务中执行。
- VisionKit 预览分析在异步任务中执行；窗口切图或关闭会取消任务并使请求失效。
- 桌面文件写入在后台任务中执行；全局同一时间最多一个保存任务，避免重复点击产生无意义副本。
- CaptureService 通过状态门保证同一时间只有一个调用。
- OCR 使用全局状态门保证同一时间只有一个调用；历史项被淘汰时，晚到结果直接丢弃。

## 11. 权限、隐私与安全

- `⇧⌘3/4` 接管需要一次辅助功能授权。应用只监听并吞掉精确匹配的两组已配置截图键，其余键盘事件原样放行；不记录按键内容，不持久化事件，也不修改 macOS 的系统快捷键设置。
- 辅助功能未授权或授权后来失效时，菜单截图入口仍可用；设置界面提供请求授权、打开“隐私与安全性 > 辅助功能”和重新检测。macOS 可能要求退出并重新打开应用后授权才完全生效。
- 每次截图触发都调用 `CGPreflightScreenCaptureAccess`，因此运行期间撤销或重新授予权限都能恢复；未授权时调用一次 `CGRequestScreenCaptureAccess`。
- 权限被拒后不在同一次操作中反复弹系统提示，只提供系统设置入口。下次截图会再次预检并调用请求 API；macOS 若不再显示系统弹窗，应用仍只展示设置入口。
- 截图通过临时文件桥接，正常、取消和失败路径均立即尝试删除；崩溃遗留文件在下次启动时按一小时阈值回收。
- 用户退出时取消应用持有的截图和 OCR Task，并向仍运行的 `screencapture` 子进程发送终止信号；退出不等待 OCR 完成，也不保存晚到结果。正常取消依靠 `defer` 删除当前临时文件。
- 一小时阈值避免误删仍可能被进程使用的近期文件。崩溃后立即重启时，未满一小时的残留可能保留到下一次应用启动；应用不为清理文件引入定时器。这是首版在“崩溃恢复”和“空闲零轮询”之间接受的限制。
- 历史仍只存在内存，不自动写入 Application Support、缓存或用户图片目录；只有用户明确点击“保存”时，所选 PNG 才会持久写入桌面。
- 不访问网络、不收集日志到远端、不包含第三方 SDK。
- VisionKit 实况文本与 Vision OCR 均完全在本机处理，不新增系统权限、不上传图片，也不持久化空间分析结果。
- 本地调试日志不得打印 OCR 全文或截图二进制内容。
- 首版关闭 App Sandbox 以运行系统截图进程；这是自用/签名直装方案，不是 Mac App Store 架构。

## 12. 非功能需求

| 类别 | 目标 |
|---|---|
| CPU | 空闲 60 秒采样平均低于 1%，无轮询任务 |
| 内存 | 启动空闲 RSS 目标不超过 50 MB |
| 包体 | Release `.app` 的 ZIP 压缩包目标不超过 15 MB |
| 响应 | 截图进程结束后 300 ms 内更新剪贴板和历史（常规图片） |
| OCR | 典型 4K 截图在本机 3 秒内完成，UI 不阻塞 |
| 稳定性 | 单个服务失败不导致应用退出或清空已有历史 |
| 可访问性 | 图标、缩略图和按钮提供文字标签；支持键盘导航与 VoiceOver |

性能数字是首版工程目标，不是对所有硬件和极端图片的通用保证。首版验收基准机固定为 Apple M1 Pro、16 GB 内存的 MacBook Pro，使用 Release 构建、断开调试器并记录 macOS 版本。CPU 和 RSS 统一用 Instruments 在启动稳定后测量；响应时间使用一张 3840×2160 PNG，从截图子进程退出计到剪贴板与历史完成更新；OCR 使用固定的 3840×2160 中英混排测试图。最终测试记录必须保存样本哈希和 Instruments 版本，换机器所得结果只作参考。

## 13. 成功指标

首版以本机可用性而非增长指标验收：

- 核心截图流程连续执行 50 次无崩溃、无残留临时文件。
- 选区、窗口、取消和主显示器四条路径全部通过。
- 历史在任意连续截图序列中始终保持 0–3 项。
- 固定兼容矩阵中的系统应用能够粘贴图片和 OCR 文本。
- 退出后重新打开，历史为空且快捷键设置保留。
- 应用空闲时没有持续 CPU 活动和网络连接。

## 15. 开发步骤

1. 安装完整 Xcode，选择有效开发目录，确认 `xcodebuild -version`。

8. 实现 `CGEventTap` 系统截图键接管、Carbon 自定义快捷键、录制设置、权限反馈、冲突回滚和恢复默认。

## 16. 分发策略

首版 Bundle ID 为 `com.local.SnapClip`，关闭 App Sandbox，不配置额外 entitlements。Xcode 工程使用用户 Personal Team 的 Apple Development 证书，使 Debug、Release 和后续重编译共享稳定的 designated requirement；不要用 Sign to Run Locally/ad-hoc 版本做屏幕录制或“登录时启动”验收。若从旧 ad-hoc 构建迁移，需用 `tccutil reset ScreenCapture com.local.SnapClip` 删除旧签名对应的 TCC 记录，再启动当前签名版本并重新授权一次。正式产物是复制到 `/Applications` 的 `SnapClip.app`，不制作安装器，也不承诺其他设备上的 Gatekeeper 体验。SwiftPM 生成的裸命令行二进制和 ad-hoc 构建不能作为系统权限验收产物。

若未来对外分发，需要单独增加：

- Apple Developer Program 与 Developer ID Application 证书。
- Hardened Runtime、签名、公证和 stapling。
- DMG/ZIP 发布流程和版本管理。
- 独立评估自动更新框架、更新包签名和 Feed 托管。

若未来上架 Mac App Store，需要替换 `screencapture` 子进程、启用 App Sandbox，并用 ScreenCaptureKit 与自定义截图选择界面重新实现截图层。

## 18. 主要风险与缓解

| 风险 | 影响 | 缓解 |
|---|---|---|
| 系统截图命令行为随 macOS 改变 | 截图流程失效 | 封装 CaptureService；保留迁移 ScreenCaptureKit 的边界 |
| 屏幕录制权限归属或状态变化 | 用户无法截图 | 启动前预检、明确恢复入口、权限回归测试 |
| 大截图导致内存上涨 | 偏离轻量目标 | 历史保存压缩 PNG，按需解码，最多三张 |
| Carbon API 老旧 | 长期维护风险 | 隔离 HotKeyService，未来可替换而不影响业务状态 |
| 登录启动依赖签名 | 裸构建中失败 | Xcode 本地签名；设置中展示系统真实状态和错误 |
| OCR 阅读顺序不完美 | 复制文本可读性下降 | 按坐标排序并保留换行；不承诺复杂排版还原 |
| VisionKit 分析较慢、无结果或晚到 | 预览文字暂不可选或发生串图风险 | 图片优先显示；提供降级状态；切图/关窗取消并用请求代次拒绝旧结果 |

## 19. 已确定决策

- 产品工作名为 SnapClip。
- 采用 Xcode + Swift/SwiftUI/AppKit，而非跨平台框架。
- 支持 Apple Silicon、macOS 14+。
- 历史仅在当前运行周期存在。
- 首版零第三方运行时依赖、无网络、无自动更新。
- 图片搜索属于后续版本，首版不显示占位入口。
